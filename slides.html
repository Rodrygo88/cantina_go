03 — Qualidade de Código

Object Calisthenics — 9 Regras Aplicadas

Regra 1 Um nível de indentação
try { await Service.criar() } catch { next(erro) }
Controllers com apenas try/catch — sem ifs aninhados dentro de loops.
Regra 2 Sem else
throw new UnauthorizedException(…)
// nunca: if (ok) { … } else { … }
Erros lançam exceção. Sucesso segue em frente. Sem bifurcação.
Regra 3 Encapsular primitivos
new Email("user@email.com")
new Id("uuid-aqui")
Strings e UUIDs viram objetos com validação embutida no construtor.
Regra 5 Sem abreviações
cantinaCriada, usuarioAutenticado
// nunca: u, obj, res2
Nomes descrevem o que são — o código se lê como texto.
Regra 6 Entidades pequenas
Controller ~95 linhas
Value Object ~35 linhas
Cada arquivo tem uma responsabilidade. Nada faz mais do que deve.
Regra 7 Acesso via métodos
email.toString()
id.toJSON() · produto.estaDisponivel()
Nenhum código externo acessa .value diretamente — sempre via método.
Regra 8 Composição, não herança
Result.created(data).send(res)
// Result contém, não herda
Result tem data e statusCode dentro — sem cadeia de herança.
Regra 9 Tell, don't Ask
Result.created(dados).send(res)
// manda fazer, não pergunta
Dizemos ao objeto o que fazer — ele não retorna estado para decidirmos fora.
Regra 10 Exceções, não ifs
throw new ValidationException()
throw new NotFoundException()
3 exceções específicas substituem ifs de validação em todo o projeto.

06 — API

REST — Como construímos nossa API

🌐
URLs com propósito claro
Cada endpoint faz uma coisa. /api/reservas cuida só de reservas — sem ambiguidade.
📄
Swagger automático
Documentação interativa gerada do próprio código — qualquer um pode testar os endpoints sem ler código.
⚡
Stateless
O servidor não guarda sessão. Cada requisição carrega o JWT — fácil de escalar e de testar.
🔁
Resposta padronizada
Todo endpoint retorna o mesmo formato { data, message } — o frontend sabe exatamente o que esperar.
Endpoints do projeto
POST /api/auth/login-usuario Login do aluno com JWT
GET /api/produtos Cardápio público da cantina
POST /api/reservas Aluno cria uma reserva
PUT /api/reservas/:id/status Cantina atualiza status do pedido
07 — Segurança

Proteção em Múltiplas Camadas

🪪 JWT + Token Versioning
Como um crachá que é cancelado na hora quando você perde o emprego — não espera vencer.
Ao trocar a senha, todos os tokens antigos são invalidados imediatamente.
🔐 bcrypt nas Senhas
Como um cofre diferente para cada pessoa — mesmo que alguém roube o cofre, não consegue abrir.
Hash com salt automático, resistente a ataques de rainbow table. Nunca texto puro.
🚨 Proteção contra Força Bruta
Como um banco que bloqueia seu cartão após 3 senhas erradas — mas aqui são 5 tentativas.
Conta bloqueada por 15 min após 5 erros. O bloqueio fica salvo no banco — sobrevive a reinicializações.
💉 Sem SQL Injection
Como exigir que o cliente preencha um formulário padrão — nunca aceitar um bilhetinho avulso.
Todas as queries usam parâmetros. Nenhuma string é concatenada para montar o SQL.
🔑 Validação de Propriedade
Como uma chave que só abre sua própria porta — uma cantina não mexe no cardápio de outra.
Verificamos o dono do recurso em toda operação de escrita, além da autenticação.
🏦 Segredos Isolados
Como guardar a chave do cofre dentro do cofre — não deixar em cima da mesa.
JWT, API keys e senha do banco só em variáveis de ambiente. O servidor nem sobe sem JWT_SECRET.
08 — Frontend

Experiência do Usuário

🚦
Rotas Protegidas por Perfil
Como uma catraca que só abre com o crachá certo.
Aluno não acessa o painel da cantina — e vice-versa. Redirecionamento automático ao tentar entrar em área restrita.
📡
Notificações em Tempo Real
Como um mensageiro que avisa na hora — sem precisar perguntar "chegou já?"
SSE conectado ao backend. Pedido atualizado pela cantina → aluno recebe na hora. Salva até 30 notificações no localStorage.
🛡️
Error Boundary
Como um airbag — se algo quebrar, o usuário vê uma mensagem amigável, não tela branca.
Captura erros de renderização do React e exibe um botão de recarregar em vez de travar o app.

09 — Acessibilidade

O site funciona para todos

🤟 Libras
Pessoas surdas
Como funciona
O botão VLibras traduz todo o conteúdo do site para Língua Brasileira de Sinais em vídeo.
🎞️ Menos movimento
Epilepsia · Vertigem
Como funciona
Se o usuário ativou "reduzir animações" no celular ou computador, o site respeita essa escolha e desliga os efeitos visuais.
🔊 Leitura em voz alta
Deficiência visual
Como funciona
Cada botão do site tem uma descrição em texto invisível. O leitor de tela do celular lê em voz alta o que cada botão faz — e avisa quando chega uma notificação nova.
⌨️ Sem precisar de mouse
Dificuldade motora
Como funciona
Todo o site pode ser navegado só com o teclado — a tecla Tab move entre os botões e Enter confirma a ação, sem precisar de clique.
